# PAIGE UI design standard

This standard follows the [ANT-147 owner direction](https://linear.app/paigeagentai/issue/ANT-147#comment-6ca6ba0d-6c3a-45a5-a8e9-41eccc790cd7) and [ANT-168 Desktop UX requirements](https://linear.app/paigeagentai/issue/ANT-168).

Start with **Flow by Flow**. Identify the user's goal, actual entry point, affected states, and how the outcome can be verified. Apply **Impeccable** to applicable UI/UX work. Inspect the current interface and its components, tokens, visual hierarchy, typography, and copy before changing them.

Choose one task-specific skill based on the main problem.

- **Game UI/UX** for layout, screen hierarchy, density, window fit, focus, and navigation controls.
- **Level Design** for journeys, landmarks, step order, backtracking, and recovery when a user reaches a dead end.
- **Animate** for timing, feedback, transitions, interruption, and reduced motion.

Prototype a new or substantially changed user journey before implementing it, using the existing Flow Prototype and owner review process. Preserve the Windows interaction patterns and PAIGE identity. Check relevant empty, loading, failure, and recovery states. Verify keyboard focus, light and dark themes, window sizes, and Windows scaling where applicable. Use screenshots and receipts from the running build to substantiate claims.

These are design methods within the current project, tools, mode, and approvals. Use existing components and APIs. If a required capability or visual proof is unavailable, state what can be demonstrated and what remains unverified.
